# HDSL 0.2.0 使用说明

## 界面与来源

`0.2.0` 直接移植并适配 HMCL 界面源码：左侧分为账户、实例、通用三组，首页右下角是启动与实例切换组合按钮，顶部提供窗口及返回操作。实例、插件、整合包等功能由 HDSL 后台处理。界面移植的来源、改动和许可见 `docs/HMCL_PORT.md`，设置页保留上游版权说明。

便携目录的 `sources/hdsl-0.2.0-source.zip` 中附有本版 HDSL 对应源码和构建脚本，`LICENSES` 中保留上游条款与原 HDSL 的 MIT 声明。

## 第一次使用

1. 保留完整的便携目录，双击其中的 `HDSL.exe`。数据默认保存在此目录，建议放在有写入权限的位置。
2. 打开设置。如果需要代理，填写 `http://127.0.0.1:7890`，点击保存。Registry 默认使用 `https://registry.npmjs.org`。
3. 在“实例管理”中打开“创建实例”。窗口会自动在后台获取 Harness 版本列表，可同时填写名称和完整版本号，也可从列表选择。获取失败时会保留已有输入与版本列表，可以点击“刷新版本”重试或继续手动填写。
4. 确认精确版本并创建实例。含 alpha、beta、rc 的版本仍属于预发布版。空白实例使用 `web` 模板，端口留空会自动分配。首页右下角按钮旁的箭头可切换当前实例。“下载运行时”页面也可以手动查询和安装版本。
5. 如果所选版本尚未安装，按钮显示“下载并启动”。首次会自动下载 Harness 和依赖，首页显示当前阶段、已解析/复用/下载/写入的包数量及已用时间；点击“查看任务”可看完整日志或取消。安装完成后继续启动，后续启动复用该版本。服务就绪后点击打开 Web。新版 Harness 的网页鉴权由本次启动地址完成，该地址仅保存在内存，不写入日志。
6. 可使用 HDSL 的账户管理绑定模型服务，也可在 Harness 工作台内自行配置。GitHub 目录查询使用公开接口，不要求提供或读取 GitHub CLI 凭据。

打包目录内置 Java、Node 和 pnpm，Harness 按所选版本联网下载。大型依赖和网络速度会影响首次安装耗时；取消后已完成的下载缓存会保留供下次安装使用。开启代理只影响本应用后续下载及子进程环境，不修改 Windows 全局代理。

## API Key 账户

在“账户”页填写账户名称、服务商、API 地址、模型和 API Key 后保存。编辑已有账户时，API Key 留空会保留原值。列表只显示账户信息，界面状态不返回明文 Key。

使用 `deepseek-official` 和 DeepSeek 官方标准 API 地址时，启动器会根据实际 Harness 使用的协议适配请求地址。第三方或自定义地址保持原样。

保存状态为“已保存 · API 连接未验证”。保存账户不会测试 API 连通性，也不会发起收费的模型请求。可以在创建实例、编辑实例或账户页将账户绑定到 HDSL 实例；切换在该实例下一次启动时生效。

API Key 使用 Windows DPAPI 按当前 Windows 用户加密保存。把目录复制到其他 Windows 用户或电脑后，通常需要重新输入 Key。启动时，HDSL 通过临时配置选择服务商与模型，并向该次进程传入所需环境变量；遇到未知 Harness 配置结构会明确报错。Key 不写入日志、分享整合包或源码包。

这里的账户只用于 HDSL 管理的 Harness 实例。独立桌面应用中的账户和插件仍由桌面应用自身管理，不会自动继承 HDSL 的账户绑定。技术细节见 [账户与下载说明](accounts-and-downloads.md)。

## 实例与版本

- 每个实例保存自己的 Harness 版本、profile、工作目录和端口。版本列表刷新不会升级任何实例。
- 修改 Harness 版本会复制**所选 profile 的可分享内容**到新实例，原实例保留。空白实例可以直接复制；初始化过的实例复制需要恢复依赖。
- 当前复制不包括其他 profile、模型凭据、会话和补丁设置。请在新实例重新配置。需要完整保留数据时，在应用完全退出后自行备份整个便携目录。
- 编辑实例可以选择已存在的 profile，支持中文名称。自定义 profile 通过整合包导入，或由相应 Harness 工具创建；空白新建流程不生成自定义模板。
- 停止操作只处理本次 HDSL 启动的进程树。端口被外部程序占用时会提示，不会停止该程序。
- 删除实例会移到 `trash`，不会立即删除磁盘数据。不要把回收目录作为永久备份。恢复需退出应用后搬回原实例目录，并恢复对应启动器元数据备份。

旧版的 `config/instances.properties` 会在首次打开时迁移到新清单，原文件保留。旧版原实例目录和自定义命令保留；不要同时用两个版本操作同一份数据。

## 整合包

选择 `.dspack` 或受支持的快照 ZIP，先检查，再导入新实例。可手动指定精确 Harness 版本；包作者的兼容性声明不等同于本机实测。

导入先校验、解包，再在实例的最终目录恢复依赖，防止 Windows 目录链接因搬移失效。全部成功后才登记到实例列表。失败文件移入 `trash/failed-import-*` 供检查，原有实例保留。

如果包自带的 pnpm 锁文件与 manifest 不一致，仅针对 `ERR_PNPM_OUTDATED_LOCKFILE` 备份原锁并刷新；其他依赖错误仍会停止安装。原锁保存在 profile 中的 `.hdsl-original-pnpm-lock.yaml`。

导出可选：

- **当前 profile**：可导出 `web` 或自定义 profile。
- **整个实例的自定义 profiles**：按 PackForge dshhome 格式导出多个自定义 profile；规范排除 `web`、`headless` 基线模板。只有基线模板时请选择单 profile。

**导出是分享包，不是完整备份。** 已知凭据路径、会话、私人设置和可能含密钥的 `cordis.patch.yml` 等补丁文件会被排除，导入后需重新配置。用户自行写入其他普通文件的秘密不一定能被路径规则识别；分享前应检查内容。

包含 vendor tarball 也不保证完全离线。未内嵌的依赖仍可能需要联网。详细格式矩阵和真实样本见项目文档 `docs/pack-support.md`。

部分新版 Harness 将 `desktop` profile 保留给 Electron 应用。这类包可以通过格式检查和恢复依赖，但仍需适配才能由 CLI 启动。预览会提示，不会自动改名或假定其可用。

## 插件

在插件页选中实例并刷新列表。可输入 npm 坐标、GitHub/Git 坐标或相对工作目录的本地 `file:`/`link:` 包。版本选择交给对应 Harness 与 pnpm，HDSL 保留未知插件字段。

外部插件、整合包依赖的安装脚本及 pnpmfile 钩子默认关闭。需要本地原生编译的插件可能无法立即工作，应根据其说明单独处理构建。安装成功仅表示包管理完成，插件功能仍需在 Harness 中验证。

### 社区插件发现

在下载中心的插件目录中搜索 [GitHub dsh-plugin 话题](https://github.com/topics/dsh-plugin)，可翻页和刷新。每页 12 个项目；GitHub 一次搜索最多提供前 1000 项，结果过多时可用关键词缩小范围。

选中项目后检查安装目标。HDSL 读取仓库 `package.json` 和声明的 workspace，再核对 npm 已发布包的名称、仓库、工作区路径及 `dsh.bundle.patch` 声明。确认后显示精确的 `包名@版本`，由用户选择目标实例并确认安装。大型 workspace 每次最多检查 12 个包，未检查部分会提示。

合集、教程、未发布包或无法确认安装方式的项目只提供“查看项目”。元数据核验不代表插件兼容性或实际功能已经测试。GitHub 未登录公开接口有请求额度；网络失败或限流时会提示，并保留相同搜索页或项目的已有缓存。

## 独立桌面端下载

下载中心按来源区分桌面端发行包：

| 来源 | 类型与范围 |
| --- | --- |
| [DeepSeek 官网下载页](https://www.deepseek.com/en/download/) | 官方桌面应用，默认来源；页面提供 DeepSeek Harness for desktop 的 Windows 下载。 |
| [anywhere-labs/dsh-desktop](https://github.com/anywhere-labs/dsh-desktop/releases) | 社区桌面应用，按其发布列表显示安装包。 |
| [dataelement/dsh-desktop](https://github.com/dataelement/dsh-desktop/releases) | 社区桌面应用，按其发布列表显示安装包。 |

官网提供的 Windows 地址为 [DeepSeek Harness Windows x64](https://download.deepseek.com/desktop/dsh-latest-windows-x64.exe)。官网下载与官方 GitHub Release 是不同入口，GitHub 没有附件不能据此判断官网没有桌面版。

点击刷新会重新查询所选来源：官方来源从官网下载页读取 Windows 链接和文件大小；社区来源读取近期 GitHub Release 并筛选 Windows x64 文件。下载显示已收取字节与总大小。发布方提供 SHA-256 时会对照校验；未提供时会明确提示，并记录本地摘要，不称为通过了发布摘要验证。取消或失败的半包不会作为可用下载保留。

下载完成后打开所在文件夹，由你运行安装程序。HDSL 不自动安装或接管该桌面应用；其账户、插件和更新在应用内部管理。

## 长期兼容

运行时按精确版本隔离并保存锁文件。启动参数通过实际安装版本的帮助检测；帮助格式变更但参数仍有效时，可在 `config/compatibility.json` 中维护能力声明，具体格式见项目的 `docs/runtime-compatibility.md`。

不能保证所有未来破坏性变更自动兼容。CLI 删除参数、改变 profile 结构、插件要求新 Node ABI 时，可能需要更新 Node、pnpm、插件或启动器。未知整合包格式会明确拒绝，不猜测其结构。

## 数据位置

| 目录 | 内容 |
| --- | --- |
| `config/launcher-v2.json` | 实例清单及启动器设置 |
| `config/accounts.json` | 账户信息及由 DPAPI 加密的 API Key |
| `instances/<id>/dsh-home` | 该实例的 Harness 数据 |
| `instances/<id>/workspace` | 默认工作目录 |
| `instances/<id>/agents-home` | 隔离的代理配置目录 |
| `runtimes/<精确版本>` | 对应 Harness 安装与锁文件 |
| `tools` | Node、pnpm 与启动包装脚本 |
| `cache` | 下载和依赖缓存、暂存内容 |
| `logs` | 按日保存的启动器及进程日志，常见凭据字段会脱敏 |
| `downloads/desktop` | 按来源保存的独立桌面端安装包 |
| `trash` | 删除的实例、运行时和失败导入 |

源码运行可用 `-Dhdsl.data=<目录>` 或 `HDSL_PORTABLE_ROOT` 指定数据根。未指定时使用用户目录下的 `.hdsl`。完整备份前请退出 HDSL，避免复制正在写入的数据。

## 本次人工验收

1. 打开界面，调整窗口大小，检查导航、设置和任务日志；逐一选择五张内置背景，保存并重启，检查选择是否保留。
2. 分别创建旧版 `0.1.0-rc.6` 和新版 `0.2.0-rc.2` 实例，启动、打开工作台、停止并再次启动。
3. 在自己的工作台中配置模型，执行一次日常操作；自动化验收没有使用真实账户或发起模型请求。
4. 导入自己使用的整合包，检查 profile、插件和资源；再验证插件的实际功能。
5. 试用复制、修改版本、导出和删除，检查原实例保留及分享导出的省略提示。
6. 打开“创建实例”，检查版本自动刷新期间仍可填写；遇到网络失败时，确认已有输入与列表保留。
7. 保存并绑定一个账户，确认状态仍标明“API 连接未验证”；重启实例后由你检查实际模型服务。
8. 搜索社区项目、检查安装目标；确认无法核验的项目没有安装入口。检查桌面下载页的来源标签、进度和摘要提示。
9. 将问题和希望调整的界面内容告诉 Codex。**本次代码仅在本地，需你明确验收通过后才上传 GitHub。**

开发者验证方法与已通过项目见 `docs/VALIDATION.md`。
